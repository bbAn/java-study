# Week 10 `break` · `continue` · 중첩 반복

## 학습 기간

2026-11-09 ~ 2026-11-16

---

지난주 `while` 은 "언제 끝나는지" 를 조건에 적었다.  
그런데 도전1 메뉴에서는 조건을 `true` 로 두고 `break` 로 끝냈다.  
조건이 아니라 "본문 중간에서 끝내기". 그게 `break` 다.

이번 주엔 하나가 더 붙는다.  
`break` 가 "이 반복문을 끝내기" 라면, `continue` 는 "이번 바퀴만 건너뛰기" 다.  
끝내는 게 아니라 다음 바퀴로 바로 넘어가는 것.  
지난주 도전2 에서 "`i += 6` 같은 꼼수는 다음에" 라고 했던 게 이번 주 `continue` 다.  
그리고 지난주 도전1 abc 처리에서 `else` 가 통째로 사라지는 것도 `continue` 로 보게 된다.

후반은 중첩 반복이다. 8주차 도전1 구구단이랑 도전2 별 찍기에서 이미 `for` 안에 `for` 를 썼다.  
이번 주는 그걸 다섯 가지 모양으로 늘리고, 소수(약수가 1 과 자기 자신뿐인 수)를 찾는다.  
그러면서 처음으로 "맞는데 느린 코드" 를 보게 된다. 6주차 표에 없던 칸이다.

### 10-2. 3 또는 5 의 배수만 — `continue`

1 부터 50 까지 중 3 또는 5 의 배수만 한 줄에 출력하세요.

```text
    3 5 6 9 10 12 15 ...
```

**조건 1: `continue` 로 쓸 것. "3 도 아니고 5 도 아니면 건너뛴다" 를 적는 겁니다.**

```java
    for (int i = 1; i <= 50; i++) {
        if (i % 3 != 0 && i % 5 != 0) continue;
        System.out.print(i + " ");
    }
```

**조건 2: 몇 개 나올지 예상부터 적고 count 로 비교할 것  
(힌트: 3 의 배수 + 5 의 배수 - 15 의 배수. 지난주 도전2 랑 반대 방향)**  
예상: 23개

| 구분       | 계산                 | 해당 숫자                                                   | 개수 |
| ---------- | -------------------- | ----------------------------------------------------------- | ---: |
| 3 의 배수  | 50 ÷ 3 = 16 나머지 2 | 3, 6, 9, 12, 15, 18, 21, 24, 27, 30, 33, 36, 39, 42, 45, 48 |   16 |
| 5 의 배수  | 50 ÷ 5 = 10          | 5, 10, 15, 20, 25, 30, 35, 40, 45, 50                       |   10 |
| 15 의 배수 | 50 ÷ 15 = 3 나머지 5 | 15, 30, 45                                                  |    3 |

16 + 10 − 3 = 23  
15 의 배수는 3 과 5 양쪽에서 두 번 세어지므로 한 번 뺌

**조건 3: 8-3 · 지난주 도전2 처럼 if 로 "할 것" 을 감싸는 방법으로도 한 번 더 쓸 것. 결과가 같은지.**

#### - 실행 결과

```
// continue
   3 5 6 9 10 12 15 18 20 21 24 25 27 30 33 35 36 39 40 42 45 48 50
   개수 : 23

// if 로 감싼 것
   3 5 6 9 10 12 15 18 20 21 24 25 27 30 33 35 36 39 40 42 45 48 50
   개수 : 23
```

![10-2-1 실행 결과](./images/10-2-1.png)

**→ if 로 감싼 것과 `continue` 로 건너뛴 것, 결과는 같은데 뭐가 다른가요. 한 줄로.  
(힌트: if 는 "할 것" 을 안에 넣고, `continue` 는 "안 할 것" 을 먼저 치웁니다. 안쪽이 깊어지나요 얕아지나요)**  
`if` 로 감싸면 할 일이 `if` 블록 안으로 들어가 깊어지고 `continue` 는 안 할 것을 먼저 치워서 할 일이 `for` 그대로 남아 얕아짐

**→ `while` 로 바꿔서 `continue` 를 `i++` 앞에 두어보세요.**

```java
    int i = 1;
    while (i <= 50) {
        if (i % 3 != 0 && i % 5 != 0) continue;
        System.out.print(i + " ");
        i++;
    }
```

**뭐가 나오나요. 예상부터. 빨간 네모로 멈추고, 어디서 멈춰 있는지 i 값으로 한 줄.  
(힌트: i 가 1 이면 `continue` 로 갑니다. 그 다음 `i++` 는 실행되나요)  
지난주 도전2 "`i++` 를 if 안에" 랑 같은 종류인가요. 한 줄로.**  
예상: 모르겠음

멈춘 지점: i = 1. 1 은 3 5 둘 다 아니라서 `continue` 로 가고 아래 `i++` 를 건너뛰어 i 가 1 에서 안 바뀜

지난주 도전2 랑 같은 종류.  
둘 다 조건에 걸린 바퀴에서 `i++` 가 실행되지 않아 i 가 멈춤

#### - 실행 결과

```

   3 5 6 9 10 12 15 18 20 21 24 25 27 30 33 35 36 39 40 42 45 48 50
   개수 : 23

// if 로 감싼 것
   3 5 6 9 10 12 15 18 20 21 24 25 27 30 33 35 36 39 40 42 45 48 50
   개수 : 23

// while + continue 가 i++ 앞
   아무것도 안 나오고 끝나지 않음
```

![10-2-2 실행 결과](./images/10-2-2.png)

**→ `for` 에서는 같은 자리에 `continue` 가 있어도 안 멈췄죠. 왜 `for` 는 괜찮은지 한 줄로.  
(힌트: `continue` 가 건너뛰고 어디로 가나요. `for` 의 세 칸 중 어디인가요)  
`while` 에서 고치려면 `i++` 를 어디로 옮겨야 하나요. 옮기고 나서 시작값은 1 이 맞나요 0 이 맞나요.**

안 멈췄다는 말이 의미가 부정확한 것 같음  
안 끝나고 계속 돌았다는 것으로 혼동됨

`for` 는 `continue` 를 만나도 `i++` 를 꼭 실행하기 때문에 i 가 늘어남  
`while` 은 `i++` 를 `continue` 보다 위로 올리면 됨  
옮기고 나서 `i++` 가 먼저니까 시작값은 0  
1 이면 2 부터 검사됨  
`i <= 50` 이면 51 까지 검사되고 51 은 3 의 배수라 찍혀서 `i < 50` 으로 수정함

```java
    int i = 0;
    while (i < 50) {
        i++;
        if (i % 3 != 0 && i % 5 != 0) continue;
        System.out.print(i + " ");
    }
```

#### - 수정 후 실행 결과

## 힌트

`break` 와 `continue`

```text
    break       이 반복문을 끝낸다. 조건식 다시 안 본다. 바로 } 밖으로.
    continue    이번 바퀴만 건너뛴다. 끝내는 게 아니라 다음 바퀴로.
```

`for` 에서 `continue` 는 증감식(세 번째 칸)으로 갑니다. 그래서 `i++` 가 실행됩니다.  
`while` 에서 `continue` 는 조건식으로 바로 갑니다. `i++` 가 `continue` 뒤에 있으면 건너뜁니다. 그래서 안 끝남.  
지난주 "`i++` 를 if 안에" 랑 같은 사고인데 이번엔 `continue` 가 범인.

중첩 반복

```java
    for (바깥) {            // 1 번 돌 때
        for (안쪽) {        // 안쪽은 전부 돈다
        }
    }
```

바깥 5 번 × 안쪽 5 번 = 25 번. 8주차 도전1 8 × 9 = 72 줄 그대로.  
바깥이 줄, 안쪽이 칸. 별 찍기 · 구구단 · 체스판 전부 이 모양.  
변수 이름 겹치면 already defined (8주차 도전1). 바깥 i, 안쪽 j.

별 찍기 표

```text
    줄 k       공백     별
    직각       0        k
    역삼각     0        n - k + 1
    오른쪽     n - k    k
    피라미드   n - k    2k - 1
    다이아     피라미드 n 줄 + 역피라미드 n - 1 줄
```

표가 맞으면 코드는 `for` 두 개 (공백용 · 별용) 랑 `println` 하나.

소수 뼈대

```java
    for (int i = 2; i <= 100; i++) {
        boolean isPrime = true;
        for (int j = 2; j < i; j++) {
            if (i % j == 0) {
                isPrime = false;
                break;
            }
        }
        if (isPrime) System.out.print(i + " ");
    }
```

안쪽에서 찾은 걸 밖으로 전하는 게 isPrime. 8-1 "안에서 만든 건 밖에서 안 보임" 때문에 밖에서 만듭니다.  
`break` 가 있어서 하나만 찾으면 멈춥니다. 없어도 답은 같고 바퀴만 늘어납니다.

시간 재기

```java
    long start = System.currentTimeMillis();     // 1970 년부터 지금까지 밀리초. long 인 이유는 8-4
    ... 잴 것 ...
    long end = System.currentTimeMillis();
    System.out.println((end - start) + "ms");
```

너무 빨라서 0ms 가 나오면 범위를 키우세요. 10000 → 100000.

레이블

```java
    outer:
    for (...) {
        for (...) {
            if (조건) break outer;     // 바깥 for 까지 한 번에
        }
    }
```

`break` 만 쓰면 안쪽 하나만. 레이블은 읽기 어려워서 실무에서는 표시 변수(flag)를 더 씁니다.

흔한 실수

```text
    while 에서 continue 가 i++ 앞에    무한 루프. for 는 증감식 칸으로 가서 괜찮고 while 은 조건식으로 바로 감
    break 로 바깥까지 나가려 함        안쪽 하나만 나감. 레이블 또는 flag
    안쪽 변수도 i                      already defined. 8주차 도전1
    1 을 소수로 셈                     안쪽 for 가 안 돌아서 isPrime 이 true 그대로. 1 은 따로 거름
    j <= i                             자기 자신으로 나눠떨어져서 전부 소수 아님. 0 개
    별 모양에 5 를 박음                n 바꾸면 깨짐. 전부 n 으로
    ■ 가 깨짐                          인코딩 UTF-8
```
